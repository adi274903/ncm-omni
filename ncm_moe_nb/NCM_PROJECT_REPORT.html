NCM-MoE Omni: Project Report

A from-scratch Next Concept Modelling notebook: a sparse mixture-of-experts over text, image and audio, predicting whole levels of codes coarse to fine. This report covers what was built, measured, fixed and decided, and what is still unverified.

  • Speed. On the RTX PRO 6000 the cheap speed knobs are exhausted at about 187-190 TFLOPS in real training (MEASURED). The next large lever, FP8, was declined because of the accuracy risk.
  • Data feed. The H100 test was feed-bound. The cause was how sources with few shards were split across workers; 12 workers fixed it. The H100 compute sweep was never run (the balance ran out).
  • Codecs. The original codecs had weak coarse levels, especially for text. A frozen-feature set (DINOv2 for images, DAC for audio, a data-fit text ladder) was built and checked before training. Image and audio codes carry a lot of learnable structure; text is limited at its coarse levels.
  • Learning. After a 0.3B-code run, all three modalities beat their constant-predictor baselines, with caption use missing for image and text. An earlier 2B-size run, with the previous codecs, also beat its baselines at every level (section 6b). The T1 run (2B codes) has finished: text and image LEARNED (image and text now use their caption and prompt), audio PARTIAL because it overfit (section 7).
  • Not yet shown. Good generated samples (text is babble, the image check never ran, audio was not judged), caption/prompt following for image and text, and any head-to-head against the old codec under identical settings.

2. Model and notebook

PieceWhat it is
Trunkd=1536, 16 layers, GQA 16/4, QK-norm, block-causal attention over levels
Experts3 modality groups x 2 SwiGLU experts = 6 experts, about 264M each (hidden 3584): about 1.58B in experts plus about 100M trunk
Active per tokenabout 364M (trunk plus roughly one expert, since two experts take half the tokens each at capacity 0.5)
RoutingGroup forced by modality; expert-choice inside the group, per level
LadderK=5 levels, ratio 4: text 1/4/16/64/256 slots, image 1/4/16/64/256 (2D grids), audio 2/8/32/128/512; vocabulary 257 (256 codes + NULL)
GenerationK forwards: level 0 sampled first, each next level in one parallel forward. The finest text level predicts all 256 bytes in parallel.

The notebook is assembled from src/*.py cells by build_nb.py (order set in run_src.py). All knobs are overridable by NCM_<NAME> environment variables.

4. Data feed

Root cause found in the code (PROBLEM then fixed). Each source is split into workers+1 parts. A source with fewer Parquet shards than parts (librispeech has 14) fell back to a row filter, where every worker re-reads the whole dataset. With 16 workers that meant 16 workers downloading the same large audio files, giving timeouts and "peer closed connection". 12 workers (13 parts for 14 shards) removed the stall.

Other settings that mattered: HF_TOKEN must be loaded before the kernel starts streaming (a kernel started before the token was written streamed anonymously and stalled), and longer download timeouts (60 s) suit flaky links.

5. Codecs: what was tried and what was measured

The model predicts discrete codes, so the codec fixes what is learnable. A diagnostic cell streams a fresh sample and reports, per level: codes used, entropy, how many bits the parent level tells about each level (with a shuffled control), and a small probe net's held-out gain over the unigram. The probe is a rough ceiling on what the big model can win at that level from the previous one.

5.2 Learned alternatives

  • Learned residual image VQ-VAE. 4,000 steps: finest PSNR 21.7 dB, +1.93 dB over k-means, passing the 0.5 dB gate; level-0 perplexity only 19; 430 s for 4,000 steps. The 12,000-step variant was stopped because MSE had flattened (0.0337 against 0.0336). MEASURED
  • Learned text VQ-VAE. Trained in 65 s. Byte accuracy from the coarse codes was 0.162, 0.170, 0.218 at L0-L2 against a 0.160 most-common-byte baseline, and 0.738 at L3, so nearly all information sat in one level. L1-L3 codes were near-uniform noise (parent explained 1%, 1%, 4%), and the commitment loss grew from 0.09 to 4.9. Not adopted. MEASURED
  • Reading of the result. A coarse summary of 4 to 64 bytes carries little reconstructible information, so text coarse levels are inherently weak. UNVERIFIED as a general claim.

5.3 Feature codecs (TOKENIZER="feat")

Frozen DINOv2-base patch features for images, DAC encoder latents for audio, both pooled up the ladder and quantized through a Tree-VQ-style hierarchy over 256 k-means leaves; text uses a data-fit byte-embedding ladder. Two bugs found in the earlier omni implementation were fixed in this port (mixed tree-depth conventions that could not build a tree for more than 256 leaves, and per-sample centering that removed content).

  • Coarser-level test. Replacing the previous level with random codes raised CE by 4.8 nats (image L4), 5.4 (audio L4) and 2.2-3.1 (text L4). The model reads real structure from the earlier levels. MEASURED

  • Training versus held-out. No overfitting for text and image; audio held-out CE was 0.25 above training. MEASURED
  • Samples. Text samples are letter and punctuation fragments with English frequencies and some "the" pieces, no words. Bigram bits per byte: real 3.93, shuffled real 6.27, unigram samples 6.52, model samples 6.20 (barely better than the controls). MEASURED

9. Open items and caveats

  • UNVERIFIED Generation quality: the image retrieval check never ran; audio was generated but not judged by ear; text is babble at 0.3B codes.
  • RESOLVED Image and text ignored the caption / prompt in the 0.3B-code run; in the finished T1 run both use it, mostly at the coarse levels (section 7). Whether generations follow captions is not checked, and the DINO image codec cannot be decoded to look at.
  • PROBLEM Audio overfits in the T1 run (training CE 1.00 against held-out 1.78, and held-out CE rose after step 753). The cause is undiagnosed; possible directions, all untested, are more distinct audio data or a different source mix, stronger regularization, and keeping the best held-out checkpoint instead of overwriting one file.
  • PROBLEM The prefix-use check threshold (0.01 nats) is too lax; about 0.05 would be more honest.
  • PROBLEM Text coarse levels are close to noise with every text codec tried; the finest level is predicted in parallel with no byte-to-byte dependence. Likely the cap on text quality. Options (all unbuilt): semantic coarse codes from a pretrained model, strided subsampling levels, or an autoregressive text path.
  • UNVERIFIED Worker counts above 16 and the shard-aware split; the cause of the IndexError at 24-32 workers.
  • UNVERIFIED DINO has no decoder, so image quality cannot be seen. The learned VQ image codec reaches about 21.7 dB, which is still blurry (the 8-bit-per-patch budget is the ceiling).
  • ESTIMATE Larger tiers on the same hardware: T2 (20B codes) about 4 days, T3 (50B) about 10 days at 56-65k codes/s; Colab units and the pod balance do not cover them.
  • H100 compute sweep, FP8, and the idea of doubling the image expert width (about 2.2B total, roughly a 25% throughput cost) were not done; the width change is only worth trying if image capacity turns out to be the limit.
  • Papers: the codec doc cites many arXiv papers; only the Next-Concept Modeling abstract (arXiv:2610.14162, a text-only multiscale residual VQ-VAE) was opened. None of the cited numbers were checked.
